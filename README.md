# Фитц 1.2.0.0

🌐 Русский · [English](README.en.md)

Фитц — настольный ИИ-ассистент на PyQt6 с анимированным персонажем Haru (Live2D). Понимает текстовые команды, отвечает через API языковой модели, управляет системой Linux, ведёт память, умеет смотреть на экран и открывать приложения.

> Версия 1.2.0.0 проверена модульными тестами и вызовами команд. Полный запуск GUI (голос, Live2D, окно чата) в этой версии **не проверялся вручную** — см. раздел «Что не проверено».

## Что умеет

- **Разговор и время:** приветствие, время, дата, шутки, помощь.
- **Система (Linux, GNOME):** состояние системы (ЦП, ОЗУ), блокировка экрана, громкость, открытие приложений.
- **Напоминания:** «напомни через 5 минут …».
- **Сеть:** погода, свой IP-адрес, проверка ссылок.
- **Поиск по истории чата:** «найди в истории <слово>».
- **Память и знания:** хранятся в `data/brain.json` и `data/intelligence.db`.
- **Персонаж Haru:** Live2D-модель в окне, реагирует на речь (lip-sync).
- **Настройки:** тема, прозрачность, размер персонажа, подключение API — через окно настроек.

## Установка

Требуется Python 3.12. Проверено на Linux (GNOME, Wayland).

```bash
git clone git@github.com:sima-lang/Fitz-1.1.5.0.git
cd Fitz-1.1.5.0
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
```

`requirements.lock` содержит точные версии, на которых проверена версия. Для Windows есть `requirements-windows.txt`, он не проверялся в этой версии.

Опционально для голоса и зрения нужны системные пакеты (например, `portaudio` для `sounddevice`, `tesseract` для OCR). Без них соответствующие функции отключаются, а остальное работает.

## Подключение API

Фитц работает без API, но разговор с языковой моделью требует ключ. Есть два способа; они совместимы.

### Способ 1 — через окно настроек (рекомендуется)

1. Запустите Фитца и откройте **Настройки**.
2. Перейдите на вкладку **🔌 API**.
3. Заполните поля:
   - **API Key** — ваш ключ (поле скрыто точками).
   - **API URL** — адрес сервиса. По умолчанию `https://api.provod.ai/v1`.
   - **Модель** — выберите из списка или введите свою. Доступны: `deepseek/deepseek-v4.1-flash`, `deepseek/deepseek-v4-pro`, `deepseek/deepseek-v4-flash`, `grok-4-flash`.
   - **Таймаут** — от 30 до 300 секунд.
4. Нажмите кнопку проверки API и сохраните настройки.
5. Включите или выключите **«Проверять API при старте»**.

Настройки сохраняются в `data/settings.json`. Ключ из этого файла подхватывается при запуске, если в `.env` ключа нет.

### Способ 2 — через файл `.env`

Создайте файл `.env` в корне проекта (он не попадает в git):

```ini
API_KEY=ваш_ключ
API_URL=https://api.provod.ai/v1
API_MODEL=deepseek/deepseek-v4-flash
API_TIMEOUT=60
```

Значение из `.env` имеет приоритет над окном настроек.

### Проверка

Команда `состояние` покажет, задан ли ключ: строка «API-ключ: задан» или «не задан». Само значение ключа не выводится.

> ⚠️ Не публикуйте ключ. Файлы `.env` и `data/` в `.gitignore`, но проверьте перед коммитом.

## Запуск

```bash
source .venv/bin/activate
python3 ui_pyqt.py
```

Логи пишутся в `data/fitz.log` (общий), `data/voice.log`, `data/brain.log`, `data/ui.log` — по модулям.

Сборка исполняемого файла: `build.py` / `build_exe.py` (PyInstaller) и `build_deb.sh`. В этой версии не проверялись на чистой системе.

```bash
pip install pytest ruff
QT_QPA_PLATFORM=offscreen python3 -m pytest test_fitz.py test_scenarios.py -q
ruff check --select F401,F811,F821,F841 $(git ls-files '*.py' | grep -v Fitz.AppDir)
```

Результат на версии 1.2.0.0: 112 passed, 2 skipped. Линтер по этим правилам чист. Полный `ruff check` показывает стилистические замечания (в основном широкие `except`), это не ошибки.

## Решение проблем

**Фитц отвечает «API-ключ не задан».**
Откройте Настройки → API и введите ключ, или добавьте `API_KEY` в `.env`. Проверьте командой `состояние`.

**Не работает погода или IP.**
Нужна сеть. Проверьте интернет и `data/fitz.log` на ошибки `requests`.

**Не закрывается окно по имени.**
На Wayland это не работает без GNOME-расширения `fitz-close@local` и перелогина. Закройте окно вручную.

**Ошибка `psutil не установлен`.**
`pip install psutil` в активном окружении.

**Нет звука или голоса.**
Проверьте микрофон и системные пакеты для `sounddevice`. Без них голос отключается, текстовый чат работает.

**Окно Haru не появляется или пустое.**
Проверьте, что в `live2d/` есть модель и что включён параметр «Haru» в настройках. Смотрите `data/ui.log`.

**Не сохраняются настройки.**
Проверьте права на запись в `data/`. Запись атомарная: при ошибке старый файл сохраняется.

**Что-то сломалось после обновления.**
Резервные копии правок лежат в `backup_before_audit/`. Версию можно откатить через `git log` и `git checkout <коммит> -- <файл>`.

Если проблема не описана здесь, посмотрите `data/fitz.log` и `data/ui.log` и приложите их к отчёту.

## Известные проблемы

- Команда «дневник» отвечает «нет модуля intelligence», хотя модуль `core/intelligence.py` есть. Ошибка в роутере команд.
- Фразы «запомни что у меня кот» и «что ты знаешь» не распознаются.
- Проверка ссылок (`security/safe_links.py`): между проверкой адреса и запросом DNS может вернуть другой адрес (DNS-rebinding). Полное закрытие не сделано.
- Ответы языковой модели в версии 1.2.0.0 проверены только модульными тестами с подменой API.

## История изменений 1.2.0.0

**Добавлено**
- Команда состояния (ЦП, ОЗУ, API-ключ без значения, размер `data/`, DLC).
- Поиск по истории чата.
- Раздельные логи по модулям.
- `requirements.lock` с точными версиями.

**Исправлено**
- SSRF через редирект в проверке ссылок: каждый шаг проверяется до запроса.
- Проверка всех адресов хоста, включая IPv6.
- Удаление файлов в `super_vision` только для скриншотов портала.
- Атомарная запись JSON (настройки, профиль, память, история чата).
- Ключ из окна настроек применяется при старте.
- Сообщения в логе описывают действие вместо вводящей в заблуждение фразы.
- Хеш изображения sha256 вместо md5; `mss.MSS` вместо устаревшего `mss.mss`.

**Удалено**
- `security/anti_theft.py` — не обнаруживал вторжений.
- Модуль DLC «greed» и ссылки на него.

**Ограничения доступа**
- Файловые команды работают только в Рабочем столе, Документах, Загрузках, Изображениях и папке проекта. Файлы прямо в домашней папке и `~/.ssh`, `~/.gnupg` недоступны.

**Не сделано**
- `CHANGELOG.md`, потоковый вывод ответов, подтверждение перед закрытием нескольких окон, smoke-тест импорта в CI, ручной запуск GUI.
